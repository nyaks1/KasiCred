# F3: WhatsApp integration for a hackathon with NO BSP and NO middleman: Meta WhatsApp Cloud API direct signup vs BSP-required paths, whether Cloud API is truly direct (no BSP), free tier/conversation pricing, webhook setup time, phone number requirements, unofficial libraries (Baileys, whatsapp-web.js, venom) ToS/ban risk and whether judges accept them for demos, and a minimal architecture that can send/receive messages in 72 hours.

## Findings

### [1] Meta WhatsApp Cloud API is a true direct (no-BSP) path: a developer creates a Meta app with the WhatsApp use case, a business portfolio, and a Messaging account in the Meta App Dashboard and calls Graph API themselves—no Solution Provider/BSP is required.
- quote: "Open the Meta App Dashboard to create a new Meta app with the WhatsApp use case. … Connect your app to a Messaging account. This connection allows your app to access the WhatsApp Cloud API and send messages on behalf of your business."
- url: https://developers.facebook.com/docs/whatsapp/cloud-api/get-started
- source_type: primary
- published: 2026-06-16 (page "Updated")
- confidence: high

### [2] Cloud API is Meta-hosted Graph HTTPS + webhooks (platform_type CLOUD_API); Solution Partners are an optional partner track, not a prerequisite for send/receive.
- quote: "The WhatsApp Business Platform Cloud API enables you to programmatically message and call on WhatsApp. … Cloud API uses Graph API for sending messages and Webhooks for receiving events, and both operate over industry standard HTTPS, protected by TLS."
- url: https://developers.facebook.com/docs/whatsapp/cloud-api/overview
- source_type: primary
- published: 2026-08-04 (page "Updated")
- confidence: high

### [3] Effective July 1, 2025 Meta charges per-message (not per-conversation); only template messages delivered outside a customer service window are billable under the current model (rate cards effective July 1, 2026).
- quote: "Effective July 1, 2025, Meta charges on a per-message basis for messages businesses deliver to WhatsApp users: You are only charged when a template message is delivered"
- url: https://developers.facebook.com/docs/whatsapp/pricing
- source_type: primary
- published: 2026-09-10 (page "Updated")
- confidence: high

### [4] For GKHACK26 (Fri–Sun 25–27 Sep 2026), demo traffic is free if it stays inside the 24-hour customer service window: non-template messages have been free since Nov 1, 2024 and utility templates in an open CSW free since July 1, 2025 (that utility freebie ends Sep 30, 2026).
- quote: "As of November 1, 2024 - Meta does not charge for non-template messages … As of July 1, 2025 - Meta does not charge for utility templates in response to users (delivered within an open customer service window)."
- url: https://developers.facebook.com/docs/whatsapp/pricing
- source_type: primary
- published: 2026-09-10 (page "Updated")
- confidence: high

### [5] A free entry point (FEP) window opens after a user messages via Click-to-WhatsApp Ad or Facebook Page CTA and you reply within 24h; for 72 hours all message types (including templates) are free—note the FEP window is independent of the CSW.
- quote: "FEP windows remain open for 72 hours. While open, you can send any type of message to the user at no charge. Note, however, that the customer service window is independent of the FEP window, so if the customer service window closes, you will only be able to send template messages."
- url: https://developers.facebook.com/docs/whatsapp/pricing
- source_type: primary
- published: 2026-09-10 (page "Updated")
- confidence: high

### [6] Starting October 1, 2026 (the week after GKHACK26), Meta begins charging service messages with a free monthly tier of 1,000 delivered service messages per business phone number (no roll-over); without a payment method, messages stop after the free tier is exhausted.
- quote: "Each business phone number has one shared free tier of 1,000 delivered service messages per month. … Unused service messages in the free tier do not roll over. … If you do not have a payment method for your WhatsApp Business account, Meta will deliver service messages within the shared free tier but not deliver them after the free tier has been used."
- url: https://developers.facebook.com/docs/whatsapp/pricing
- source_type: primary
- published: 2026-09-10 (page "Updated")
- confidence: high

### [7] Cloud API signup auto-provisions a test WhatsApp account, test Messaging account, and test business phone number with relaxed messaging limits and no payment method required for templates—this is the shortest legal path for a 72-hour demo.
- quote: "When you get started with Cloud API, a test WhatsApp account, test Messaging account, and test business phone number are automatically created for you. Test accounts and test phone numbers are useful for testing purposes, as they have relaxed messaging limits and don't require a payment method on file in order to send template messages."
- url: https://developers.facebook.com/docs/whatsapp/cloud-api/overview
- source_type: primary
- published: 2026-08-04 (page "Updated")
- confidence: high

### [8] Phone number requirements for Cloud API: number must be owned by you, have country/area code (no short codes), accept SMS or voice OTP, and must not already be on WhatsApp Messenger (delete first if so); new business portfolios start capped at 2 registered numbers; mobile SIMs are the reliable OTP path (VoIP/personal types are "Not Recommended" for SMS OTP).
- quote: "Eligible phone numbers must: be owned by you; have a country and area code (short codes are not supported); be able to receive voice calls or SMS"
- url: https://developers.facebook.com/docs/whatsapp/phone-numbers
- source_type: primary
- published: 2026-05-21 (page "Updated")
- confidence: high

### [9] Webhook setup is hours, not days: expose HTTPS with a valid TLS cert (self-signed not supported), implement Meta's GET hub.challenge verification plus POST event notifications, optionally signed with X-Hub-Signature-256; Cloud API docs also ship a sample webhook/echo-bot test path for first inbound message.
- quote: "Your endpoint must be able to process two types of HTTPS requests: Verification Requests and Event Notifications. Since both requests use HTTPs, your server must have a valid TLS or SSL certificate correctly configured and installed. Self-signed certificates are not supported."
- url: https://developers.facebook.com/docs/graph-api/webhooks/getting-started
- source_type: primary
- published: unknown
- confidence: high

### [10] Meta explicitly prohibits unauthorized third-party tools for WhatsApp Business Platform use—the direct ban/ToS hook against Baileys/whatsapp-web.js/venom-style reverse-engineered clients when used as a business integration.
- quote: "All WhatsApp Business Platform use must comply with our terms and policies. Using unauthorized third-party tools is prohibited."
- url: https://developers.facebook.com/docs/whatsapp/cloud-api/overview
- source_type: primary
- published: 2026-08-04 (page "Updated")
- confidence: high

### [11] whatsapp-web.js's own README states WhatsApp does not allow bots or unofficial clients and blocking is not avoidable—project self-documents ban risk.
- quote: "Also it is not guaranteed you will not be blocked by using this method. WhatsApp does not allow bots or unofficial clients on their platform, so this shouldn't be considered totally safe."
- url: https://github.com/wwebjs/whatsapp-web.js
- source_type: community
- published: unknown (repo live as of 2026)
- confidence: high

### [12] Baileys (WhiskeySockets) is a reverse-engineered WhatsApp Web socket library and its maintainers disclaim ToS-compliant use and discourage automated/bulk messaging; Venom v6 similarly models TOS_BLOCK as a first-class connection state, i.e. ToS bans are an expected failure mode.
- quote: "The maintainers of Baileys do not in any way condone the use of this application in practices that violate the Terms of Service of WhatsApp. … We discourage any stalkerware, bulk or automated messaging usage."
- url: https://github.com/WhiskeySockets/Baileys
- source_type: community
- published: unknown (repo live as of 2026)
- confidence: high

### [13] Minimal 72h no-BSP/no-middleman architecture that matches the docs: Meta App (WhatsApp use case) + auto test number + Graph POST https://graph.facebook.com/v23.0/<PHONE_NUMBER_ID>/messages + FastAPI HTTPS webhook (tunnel ok for demo) + reply only inside the open 24h CSW with free `"type":"text"` non-template messages; optional Python wrapper PyWa exists but is explicitly not Meta-maintained or endorsed.
- quote: "Some SDKs, like PyWa (Python wrapper), are available but are not maintained or endorsed by Meta."
- url: https://developers.facebook.com/docs/whatsapp/cloud-api/overview
- source_type: primary
- published: 2026-08-04 (page "Updated")
- confidence: high

### [14] WhatsApp Business Platform Terms (effective Sep 23, 2026) require business/commercial use and permit Meta to suspend/terminate access at its sole discretion—relevant if a hackathon demo is framed as production business messaging on an unofficial channel.
- quote: "We may modify, suspend, or terminate Company's access to or use of our Platform Services and these Terms at any time and for any reason, permissible by applicable law, including if we determine, in our sole discretion, that Company violates these Terms, receives excessive negative feedback, or creates harm, risk, or possible legal exposure for us, our users, or others."
- url: https://www.whatsapp.com/legal/WhatsApp-Terms-for-WhatsApp-Business-Platform
- source_type: primary
- published: 2026-09-23 (Effective date)
- confidence: high
